# 星を維持する点数帯変更：変換エンジンと接続設計

2026-10-20。要件は `score-band-update-requirements.md`。今回は変換エンジンを実装し、アプリ起動・保存への接続前で区切る。`app-score-policy.js` は index.html に読み込ませていない。本番・既存保存データには適用していない。

## 変換の決定

旧帯 `[a,b]`、新帯 `[c,d]` に対し `c + Math.round((score-a)*(d-c)/(b-a))`。人数による配分やタイトルによる再採点はしない。0〜49点は変換しない。50点は旧★1なので54点になる。51〜53点は新規採点時に★0.5として利用できるが、既存★1作品をそこに移さない。

例：旧★3の81/82/83は76/79/81。旧★3.5の84/85/86は82/85/87。帯が広がって空く点数は将来の採点に使う。旧50/51点は54点へまとまるが、元の51点作品を50点作品より上に置く。

順位は旧点数の降順、それぞれの `rankOrder` 順で連結する。保存順位のない作品だけ、現行 `originalSort` と同じカテゴリ・order・_seqで末尾に補う。重複ID、存在しない作品の順位、実際の点数と異なる順位所属は処理を拒否し、推測で修復しない。

## 「星」のコード上の違い

採点済みランキングの星は `STAR_RANGES`、詳細の採点済み星は `scoreToStar` で決まる。一方、`filmStar` は `starOverrides` / 作品のstarを読み、Letterboxd同期等で別の値が入ることがある。変換は画面の採点済み星を維持し、別途保存された星も書き換えない。未採点の星は従来どおりその保存値を使用する。両者の既存不一致を、この作業で勝手に整合させない。

シーズン点数は `app-seasons.js` で独立した0〜100の数値として編集され、星や全体ランキングには接続されていない。今回は `seasonScoresV1` をそのまま維持する。将来シーズンにも帯を適用するなら別途明示する。

## 実装済みの純粋処理

- `plan(state, baseFilms)` は元のJSON全文と変換候補を返す。入力、DOM、ストレージ、通信は変更しない。全BASE_FILMSを渡す必要がある。
- exactScoresの未登録/null/0を区別。oldScoreによる実効点数は新exactScoresへ明示し、作品の歴史的oldScoreは保持する。
- レビュー・履歴・ジャンル・星・シーズン・未知フィールドは維持。旧storageIntegrityは候補からのみ除き、保存時に既存のseal処理で再計算する。
- 候補に `scorePolicy: "balanced-v1"`。現在マーカーは再変換しない。未知/nullマーカーは拒否。マーカーなしを旧形式と解釈するのは、後述の「旧データ取込」入口だけに限定する。
- `matchesSource` は計画後の追加編集を検出する。これは書込排他ではない。コミット時には既存の多タブ排他とディスク基準比較が別途必要。
- 元JSONを返すことはバックアップ保存成功を意味しない。ディスクへの書込・再読込確認はまだ未実装。

## 次に実装する接続条件

旧版は新マーカーを理解しないため、マーカー追加だけでは旧版の上書きを防げない。新版は独立した保存領域で開始する。単にnormalizeStateで旧データを常時変換する方式は禁止。

1. 更新版用localStorageキー、IndexedDB名、多タブchannel/lock/receipt/復旧候補領域を独立させる。旧領域は読取のみ。ビュー設定以外の書込経路を網羅し、旧領域の全キーとIDBが変わらないテストを置く。
2. 初回は既存の完全性・候補競合チェックを通した最新旧stateから計画。変換前JSONを保護領域へ保存して再読込し、ユーザーもJSON出力可能にする。バックアップ失敗なら移行しない。
3. 変換中に元state/元ディスクが変わったら候補を廃棄して再計画。候補の作品件数、全順位列、各作品の新旧表示星、無関係データを検証。新領域へ通常の保存保証付きで書き、再読込一致後にだけ移行済み扱いにする。途中終了時、旧データは残り、次回は完成済み新stateを優先。書込結果不明なら読み直し、同じ点数に再変換しない。
4. `STAR_RANGES`、`scoreToStar`、DEFAULT_MAP、新規追加・ドラッグ・点数入力・星ジャンプ・分布・監査CSVを同じポリシーに統一。旧固定点数の補正/復旧コードは新版で実行しない。変換候補に残るrankRecovery等の旧監査情報を、新帯に対する復旧命令として使わない。
5. 旧JSONは明示した取込入口だけで変換。現在データへ無条件置換せず、変換済み同士として既存の競合比較・レビュー選択へ渡す。マーカーなしJSONを新形式として読まない。新JSONからマーカーを除去しない。
6. GitHub同期は旧 `live-state.json` と共有しない。新版専用の同期先と形式識別の準備が整うまでは新版のGitHub自動取得/保存を無効にし、理由を表示する。旧端末の書込みもある共有ファイルで片側のガードだけを頼りにしない。同期先の作成・公開は別途承認時に行う。
7. Letterboxdの星は変換対象でない。RSS更新によって新点数を旧点数へ戻さないことを既存レビュー/同期テストに追加。TMDB等のメタデータは変更しない。

独立領域の代償として旧版と新版の編集は自動では一体化しない。公開切替時に最新版JSONを取り込み、差分を確認する。旧版を並行編集し続ける運用まで解決済みとは扱わない。同期再開条件と戻し方は公開前にユーザーへ提示する。
