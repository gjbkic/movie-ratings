# Letterboxdレビューの誤manual修復

原因：app-core.jsのmemoSave77が本文の変更に関係なくmanualと編集日時を設定し、collectReviewsは保存済みGUID本文を確認せずmanualを除外していた。

修正：編集開始時の本文と現在の保存本文を比較し、無変更保存ではデータに触れない。改行コードCRLF/CRのみLFと同一視し、空白・句読点等の意図した変更は保護する。編集開始後に同期した場合も、無変更の古い編集画面で新しい本文を戻さない。

同期では同じGUIDのrssReviewRecords.bodyまたはblockと現在の本文全体が一致する場合のみmanualとnoteEditedAtを解除する。比較記録なし・部分一致・独立したメモのある本文は引き続き保護する。blockが空でも本文全体がold.bodyなら同じGUIDで置き換え可能にする。置換文字列の$記号を特別扱いせず本文として保持する。スキーマ追加や個別作品IDのハードコードはない。

Chrome隔離架空740作品テストletterboxd-reviewを通常runnerへ登録。ユーザー提示の下妻物語の旧本文、新本文、GUIDを架空作品に割り当て、誤manual修復、無変更保存後の再更新、1文字変更保護、複数同期の重複なし、block空の修復、記録なし保護、複合本文保護、再読込を確認。点数・星・順位等と対象メタデータの他フィールドを比較する。既存LB同期で行われる星正規化を先に実行してから比較基準を取得。保存整合性checksumと更新日時はレビュー変更に伴い変わるため比較対象外。

既存letterboxd（RSS/CSV/再読込）およびsheet-data-uiの5件も成功。全回帰スイートは今回未実行。実データ・本番RSS・本番ブラウザは操作せず、本番下妻物語の現在のレコードがこの条件を満たすかは未確認。公開後のLB同期で確認が必要。iPhone実機未確認。履歴記録が失われたmanual本文について、安全な根拠なしの自動解除は行わない。
