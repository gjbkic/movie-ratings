# 第④段階② 採点・順位計算の境界

現在有効なv75 effectiveScoreだけをapp-rank-queries.jsへ分離。初期の旧scoreMap/tier版は起動順序の互換性のためその位置に残す。v75の代入位置を維持する。exactScoresの所有プロパティを優先し、null/undefined/空文字/不正値は未採点、0は採点済み、キー不在だけoldScoreへフォールバックする。従来のNumber変換（真偽値や空白も含む）は変えない。

originalSortはfilmCategoryを、rankSortedはrankOrderとoriginalSortを引数で受ける。既存の入力配列sort・同一配列返却・作品参照・重複保存IDの最後勝ち・欠落時のカテゴリ/order/_seqフォールバックを維持。保存順位自体には書き込まない。

rankInfoはallFilms/effectiveScore/rankSortedの現在の関数を受け取り、元の呼出し順を維持する。allFilmsの全結果や計算値を永続キャッシュしない。未採点をNumber(null)=0として0点帯に含む既存表示挙動も今回変更しない。この表示問題は別の不具合修正として要件・期待順位を定義して扱う。

## 検索の後続設計レビュー

app-core.jsの構造化メタデータ導入部は以前のmatchを呼ばず全面置換する。後続の形式・媒体・制作地域はOR拡張。app-enhancements.jsでは保存済み監督/製作者、GitHubカタログの監督別名、手動監督の日本語別名、カタログタイトルを順次OR拡張する。最後にapp-cast.jsが出演者を追加する。各カタログは非同期に置換されるため、起動時に一度だけ検索文字列を作るキャッシュは更新漏れを招く。

次の変更単位は、構造化メタデータによる基礎検索の純粋関数化と、拡張条件の登録順序を明示すること。先に検索結果ID集合の差分テストを作る。タイトル・原題・英題・ジャンル・媒体・制作地域・形式・年・上映時間・監督/製作者・手動別名・カタログ別名/タイトル・出演者を個別入力し、読み込み前後/手動更新後/state復元後で比較する。全角/半角、記号のみ、空白、空入力の扱いが各ラップで異なるため一律正規化しない。

検索解除後の全体順位への移動は画面層の責務として維持。検索結果IDだけからrankOrderを再構築しない。計算分離に合わせて入力イベントや描画ラップを同時に変更しない。
