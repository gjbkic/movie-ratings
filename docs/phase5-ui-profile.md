# 第⑤段階：描画計測の入口

実行：node scripts/regression/ui-profile.cjs。既存harnessで架空740作品を使い、外部通信はすべて遮断する。MOVIE_APP_ROOTで比較対象チェックアウト、MOVIE_PROFILE_OUTPUTで出力先を指定できる。新旧に同じ操作を実行し、全stateが操作前後で完全一致することを確認する。通常のallゲートには時間閾値を追加しない。

対象：ランキング再描画3回、検索入力/解除、採点済み/未採点の詳細切替、同じ詳細の再整形3回。MutationObserverによるDOM変更数と同期処理時間を記録する。160ms観測窓外の処理、実機Safari、画像通信/デコード、メモリ量、スクロールの合成負荷は未測定。

14739b1のChrome155/390x844での参考結果：ランキング1回につきchildList3699件・属性8103件、詳細の同一状態refreshはchildList10件・属性3件が毎回発生。全state不変。全回帰テストと並行実行したため、この初回の処理時間は比較基準に使わない。性能比較時は他のブラウザテストを止め、同一端末/ビルドで複数回測り中央値を比較する。

安全な次の候補：app-detail-layout.jsのpreviewは毎回replaceChildrenし、tidyは同じtextContentや属性を再代入する。表示値が同じなら書き換えを省ける余地がある。ただし別ラップがDOMを作り直すため、文字列キャッシュだけで判定せず現DOMも比較する必要がある。分類切替、素早い作品切替、折り畳み、非同期更新後に正しい表示となることを既存detail-unified＋追加のDOM保持検証で固定してから変更する。

大きいランキング全再描画は後続の対象。検索中/解除後の未確定欄、ポスター、星ジャンプ、ドラッグ、順位移動の後処理順を保ったまま分割する。今回、この計測だけを理由にラップを削除していない。
