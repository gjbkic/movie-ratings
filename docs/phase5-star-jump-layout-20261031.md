# 星ジャンプの同期レイアウト読取りを減らす（第⑤段階の限定変更）

## 原因と変更範囲

架空740作品を隔離Chromeで描画したCPUプロファイルでは、ランキング再描画中の `getBoundingClientRect` が最大の自己時間だった。呼出し元は `app-core.js` の旧 `renderJumpBar`。毎回カードを作り直した直後に `.top` の高さを同期測定していた。

後続の `app-enhancements.js` の v97 は、星ジャンプをCSS変数で配置し、旧処理が設定したインライン `top` を解除する。ヘッダーとジャンプバーの高さ変更は `ResizeObserver` と `resize` により再測定する。このため、旧処理の毎回の読取りは最終表示に寄与せず、DOM再構築後のレイアウト確定を強制していた。

今回、旧処理の初回配置は後続スクリプト不在時のフォールバックとして残し、v97が有効な後はランキング再描画・旧resizeハンドラでヘッダーを測定しないようにした。星ボタンの生成、クリック、ドラッグ、順位、保存形式は変更していない。

## 計測と検証

- 変更前の診断では、8回の連続再描画で `renderJumpBar` 配下の `getBoundingClientRect` がCPUプロファイル最大のサンプル数だった。Chromeのサンプリング計測であり、実機の所要時間ではない。
- 同一マシン・同一fixtureで旧/新コードを交互に測る診断では、4回の再描画中央値は旧版が約265–396ms、新版が約191–215ms。環境変動があるため一定の短縮率を保証しない。
- `star-jump-layout.cjs` は、再描画中の旧ヘッダー測定0回、ヘッダーと星ジャンプの位置一致、高速スクロール相当の位置、ヘッダー高さ変更後の追従、映画state不変を検査する。通常回帰ランナーへ追加した。
- 変更後の `node scripts/regression/run.cjs all` は49/49スイート成功。保存、MULTITAB 18件、履歴15件、ドラッグ、検索、詳細、同期を含む。
- Chromeの自動検査はiPhone Safariの合成スクロールを証明しない。実機では星ジャンプの引っ掛かりや位置ずれを引き続き確認する。

この変更は所有者限定の架空サイトとDraft PR #12で先に検証する。main・本番映画データは変更しない。
