# 独立した移行チェックポイント

2026-10-20。app-score-migration-store.jsはindex.htmlに読み込ませず、起動処理からも呼ばない。実データ・本番・既存DBには未接続。

固定DB `movie30_balanced_migration_v1` の `migration` ストアだけを扱う。旧localStorageや既存アプリのIDBに書かない。入力は変換前と変換後のJSON文字列。commitは同じreadwriteトランザクションでbefore-conversionとcurrentを保存する。完了後、別のreadonlyトランザクションで双方の全文一致を確認する。読戻し不明ならuncertainとし、保存成功と扱わない。

既存レコードがある場合、両JSONが完全一致すればalready-committed。異なる候補や部分的/破損した記録ならconflictを返し、上書き・削除しない。異なる2タブのreadwrite処理はIndexedDBのトランザクションで直列化される。バックアップは一度だけ保存し、処理のたびに増やさない。

これは移行のチェックポイントであり、通常の編集保存ストアではない。既存候補を更新するAPIや自動マージは持たない。新しい通常編集保存先への引渡しは未実装。

## テスト

score-migration-storeを通常回帰ランナーへ登録。未実装時にテスト失敗を確認後、隔離Chrome・架空740作品で次を検証し成功。

- 空状態、原子保存、全文読戻し。
- バックアップ書込み後に、候補書込みをQuotaExceededErrorとtransaction.abortで中断。両方とも残らない。
- 同一操作の再実行、別候補の拒否、不正な形式の拒否。
- ページ再読込み後の同一データ、旧localStorage不変。
- 同じoriginの実2タブで同時に異なる候補をコミット。片方だけ確定、もう片方は競合。
- バックアップ欠落の破損記録を検出し、再コミットしても自動補修/上書きしない。

容量不足は書込失敗の注入であり、ストレージ全体の物理容量枯渇をこのテストで確認したものではない。ブラウザプロセス強制終了/OSクラッシュと実機Safariは未検証。IDBのトランザクション完了/読戻しは、OSクラッシュを越える絶対的耐久性を保証しない。

## 接続前のAstraレビュー

この部品の入力検証は形式識別と主要構造だけ。変換結果が正しいこと、元データのチェックサム、完全性、rank所属、最新ディスクとの一致は呼出側で検証しなければならない。変換エンジンの出力だから安全と仮定せず、plan.sourceJsonと現在状態/旧ディスクの比較をコミット直前に行う。

特にこの独立DBのトランザクションだけでは旧DBやlocalStorageの別タブ編集を排他できない。旧版が参加しない新しいlockを用意するだけでも足りない。移行元の固定・再確認と、完了後の旧版編集を新版へどう取り込むかの境界をAstraで確認してからアプリに接続する。新同期先の公開や実データ移行はまだ行わない。
