# カード装飾の最小レビュー（e9f3326）

利用枠節約の依頼により今回は静的確認と設計のみ。アプリコード・保存データは変更しない。

## 確認した依存関係

- app-core.js:549のMEDIA_LABELSはmovie/documentary/otherだけ。annotateTypes（631付近）はseriesやdramaにも最初は既定の「映画」を入れる。
- fixSeriesPills（687付近）はseriesだけを「ドラマ・シリーズ」に置換する。dramaには適用しない。
- fixBadges34（3600付近）は既存media-pillを前提に、series/dramaを「TVシリーズ」、otherを「その他」、それ以外を「映画」に置換する。先行処理を消すと、最終処理が置換するノード自体がなくなる。
- 950付近の描画とannotateStructured（1491付近）は既存media-pill.outerHTMLを取り出してrank-meta全体を再生成する。その間にannotateRawGenres（1065付近）がgenre-lineを追加・更新する。
- これらはdocument全体を走査している。基礎renderRankだけで同じ最終表示を作っても、後続生成カードや他領域を含めた同値性は未証明。

## 判断

種別名を一つのラベル関数へ置換して古いラップを削除する案は現時点では採用しない。documentaryなども最終処理で表示を上書きされており、「正しそうなラベル」への変更を高速化と混ぜない。まず現在の最終表示を契約として固定する。

次のSol中の作業は、小さな比較・計測テストの追加まで進められる。架空データにmovie/series/drama/documentary/other/未知種別と複数ジャンルを用意し、基礎カード・後から追加されるカード・検索解除・種別変更後の最終ラベルとジャンル順を記録する。既存rank-viewの新旧比較だけでは装飾自体を変更した比較にならないため、装飾の基準コードも固定する。

その上で各装飾関数のDOM書込み数と最終表示を比較し、書込み省略が可能な一処理から検証する。中間DOMを他処理が参照するため、初めから全装飾を末尾へ移さない。呼出し順の再構成や旧ラップ削除が必要になった時点でAstra中の設計判断へ戻す。
