# 第⑤段階：描画ラップ統合の設計レビューと最初の境界

基準fb0fb86。結論：起動末尾で全関数を一括置換したり、全処理を一つのafterイベントに移す設計は採用しない。各ラップは過去の関数を捕捉し、外部のイベントにも古い参照が残る。後処理の呼び出し順を変えると、未確定ポスター、分類状態、ドラッグ中の表示を損ねる。

段階移行の方式：同じスクリプト位置で元関数を捕捉し、decorate(render,{before,after})に明示的な前後処理を渡す。this/引数/戻り値の同一性を維持。例外を握りつぶさず、元描画が失敗した場合afterは動かさない。Promiseをawaitしない（旧ラップ同様に同期の後処理）。後処理の返り値で元の戻り値を変更しない。全体イベントバス、描画の一括遅延、debounce、再入禁止は導入しない。

最初の移行：app-unrated-panelsの末端renderRankとapp-detail-layoutの末端openSheet。順位は旧描画→dragCtx確認→星未確定→点数未確定→ジャンプ→ポスター。詳細は別作品なら分類を閉じる→旧openSheet→lastId更新→tidy。同作品の分類開閉、0/120ms整形、selectedIdガードは既存のまま。新モジュールは両スクリプト直前にロード。後続data-cleanup/bootに両関数の再代入はない。search-stabilityのoninputは実行時のrenderRankを参照する。

互換テスト2件で入れ子順序/this/引数/戻り値/例外/Promiseを固定。関連UI7スイートと全state不変の計測を実施。これは2ラップの呼出規約整理であり、31/30個のラップ削除完了や高速化ではない。

後続の移行条件：各ラップのbefore/after、置換型（元関数を呼ばない）、遅延型を区別する。before/afterだけの単純ラップを同じ位置で1件ずつ移行し、後続が旧参照を捕捉している場合は位置を動かさない。置換型・setTimeout型・非同期API結果に依存する人物/シーズンの統合は独立レビュー。例外/返り値を変えるラップは今回decorateの対象外。全描画統合を急がず、各画面の状態比較を先に固定する。保存/同期の整理は第⑥。

次の限定実装はSol中で可能：既存末端2箇所を起点に単純同期ラップだけを列挙し、上記基準に合う1件を移行。機能削除やイベントの統合、順位アルゴリズム変更はしない。大きい描画置換は再度設計判断を行う。

最終結果：互換テスト2件、関連UI7スイートすべて成功、ui-profileで全state不変を確認。今回全27スイートは未実行（直前検索版の全26成功とは区別）。diffチェック成功。iPhone実機では未公開変更のため未確認。
