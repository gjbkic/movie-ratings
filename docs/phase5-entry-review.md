# 次の画面整理の安全な入口（ca1d34cでの静的確認）

ASTで主要識別子への直接代入を数えるとrenderRank31、openSheet30、render2、addFilm5、save4。これはソース上の代入数で、実行時に有効なラップ数や不要コード数ではない。window経由や条件付き実行、以前の関数を捕捉した参照は別途追跡する必要がある。位置一覧はtest-results/ui-wrapper-inventory.json（ローカル調査出力）。

app-detail-layout.js194のopenSheetラップは分類欄の開閉状態を同作品だけ保持し、元関数の戻り値・this・追加引数を返す。その後tidyで既存パネルを整形する。単純にこのラップを除去すると分類欄や採点済み/未採点の表示が変わる。編集イベントは古いチップ側の伝播停止より先に捕捉し、0/120ms後に選択IDを確認して再整形する。遅延は古いハンドラの書込みとの順序依存があるため、不要と断定しない。

app-unrated-panels.js54のrenderRankラップはdragCtx中を避け、2つの未確定欄を整形して星ジャンプを更新し、最後にポスター装飾を適用する。最後のポスターフックは今回のiPhone表示漏れを防ぐため必須。描画後処理の統合で順序を崩さない。

推奨順序：まず描画/詳細表示の開始・終了と呼出し回数を隔離テストで測る。その後、末端の詳細整形と未確定欄整形を明示的な描画後処理へ移し、1処理ずつ旧ラップを置換する。非同期に作られる監督/出演者/シーズン欄が揃う前に装飾を完了扱いにしない。保存・同期ラップは第⑥段階まで変更しない。

検証項目：採点/未採点、同作品の再表示と別作品切替、分類開閉、点数/上映時間/ジャンル編集、早い連続切替、下スワイプ、人物→詳細、ポスター拡大、非表示作品の順位維持。DOM変更回数・関数呼出し回数・長時間タスクを新旧で計測し、操作や保存内容が同じであることを優先する。

第⑤段階の実装は未着手。第④段階の検索基礎分離とは別変更にする。
