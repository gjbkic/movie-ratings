# 第④段階・残る検索拡張の整理順

14739b1で静的追跡。app-core.js1507のstructuredMatchは以前のmatchを捕捉せず上書きするため、それ以前のジャンル等のラップを最終検索の一部と数えない。ただし起動途中の旧描画が呼ぶ可能性があり、これだけで削除可とはしない。

以降の最終match経路：core1905形式→3428媒体→3555媒体/制作→enhancements409監督/製作者→447カタログ監督別名→860日本語監督別名→944カタログタイトル/別名→cast66出演者。各段で以前のmatchを先に試し、短絡評価する。app-enhancements313などのローカル変数matchは関数ラップではない。

統合前に固定する違い：基礎は小文字化のみ、監督はNFKC＋trim、監督別名/出演者は文字・数字以外を除く。すべてを同じ正規化へ変えると検索結果が変わる。カタログは別々の閉包へ非同期に到着し、出演者は別IndexedDBのMapへ読込/取得される。起動時だけの固定検索インデックスでは手動変更や取得完了を反映できない。

次回は架空の監督・別名・出演者・カタログを注入し、読込前後/手動変更後/空文字/記号のみ/全角/複合語の最終結果IDを固定する。その後、正規化の違いと短絡順を維持した純粋predicateに1段ずつ分離する。外部サービスへ接続せず、実カタログや実作品情報をfixtureに持ち込まない。全体matchを即座に置換しない。
